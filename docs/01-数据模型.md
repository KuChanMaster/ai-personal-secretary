# 01 数据模型

以下为阶段 0 的逻辑数据模型，描述实体和字段，不含具体代码。

## 1. 用户与身份
实体：用户档案
- 用户 ID：系统生成的唯一标识。
- 匿名标识：首次打开自动生成的标识。
- 绑定邮箱：可选，用于跨设备恢复和账号找回。
- 时区：默认 Asia/Shanghai。
- 提醒偏好：免打扰时段、每日通知上限、是否启用各类提醒。
- 创建时间、更新时间。

## 2. 任务
实体：任务
- 任务 ID：唯一标识。
- 用户 ID：归属用户。
- 标题：必填。
- 备注：可选。
- 计划日期：任务计划执行的日期，可为空。
- 到期时间：可为空。
- 提醒时间：可为空，MVP 每个任务只支持一个提醒。
- 状态：进行中、已完成、已归档、已删除。
- 完成时间：完成时记录。
- 来源：手动创建、明日计划转入、AI 草稿（后续）。
- 优先级：MVP 暂不做复杂优先级，仅支持“重要”标记，可为空。
- 创建时间、更新时间。
- 删除标记：软删除，保留墓碑记录用于同步。

## 3. 每日复盘
实体：每日复盘
- 复盘 ID。
- 用户 ID。
- 日期：按用户时区的一天。
- 今天完成：文本。
- 遇到的问题：文本。
- 明日三件事：最多三条。
- 是否已转为任务：记录转换状态。
- 创建时间、更新时间。

## 4. 独立习惯（后续阶段，MVP 暂缓）
实体：习惯
- 习惯 ID、用户 ID。
- 名称。
- 周期：每天、每周若干次等。
- 是否启用。
- 创建时间、更新时间。

实体：习惯打卡记录
- 记录 ID、习惯 ID。
- 完成日期。
- 完成时间。

## 5. 通知记录
实体：通知记录
- 记录 ID。
- 用户 ID。
- 关联任务 ID，可为空。
- 通知类型：任务到期、逾期跟进、晚间复盘、连续打卡等。
- 计划发送时间。
- 实际发送时间。
- 渠道：安卓 Web Push 等。
- 状态：待发送、已发送、失败、已取消。
- 去重标识：防止同一任务同一时间重复通知。

## 6. 同步字段约定
- 所有会跨设备同步的实体都包含：创建时间、更新时间、删除标记。
- 日期和时间统一保存为 UTC，展示时转换为用户时区。
- 冲突策略 MVP 版：同一实体以“更新时间较新者”为准。
- 已删除数据保留墓碑记录，避免离线设备把已删除数据重新同步回来。

## 7. 数据权限
- 每个实体都包含用户 ID。
- 云端通过行级权限保证用户只能读写自己的数据。
- 未绑定账号的匿名身份也拥有独立、隔离的数据空间。
